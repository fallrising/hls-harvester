# Software Design Document: hls-harvester

## 1. 概述

hls-harvester 接受影片頁面 URL，在獨立的 Playwright 瀏覽器中找出播放器使用的 HLS 播放清單，供使用者在本機播放或下載。適用於有權存取與保存的影音，包括播放後才載入清單、網址帶有短效簽章，以及清單與影音分段由不同網域提供的情況。

「乾淨播放」指本地播放器只讀媒體，不載入原頁的腳本、彈窗及跳轉。原先已插入媒體串流的廣告會隨影音保留。串流播放也受上游可用性和網路狀況影響。

本文件定義預期行為。第一個實作里程碑是以本機測試頁完成「輸入 URL → 擷取 → 下載 → 用 ffprobe 驗證輸出」。即時播放與下載共用同一個本地 HLS 代理。AI 選片是選做實驗，基本流程可以離線驗收。

## 2. 系統架構

| 元件 | 責任 |
|---|---|
| CLI | 接收頁面 URL、模式、畫質與輸出路徑，回傳本地播放 URL 或已完成的檔案路徑。 |
| Playwright 與站點適配器 | 觀察播放器請求，解析 HLS 候選、媒體間的關係與標題。 |
| 快取與工作階段 | 依來源站、影片、登入工作階段保存擷取結果與有效期限。 |
| 本地 HLS 代理 | 解析及重寫清單 URI，依目的地取得資源，為每次上游請求選取適用憑證。 |
| FFmpeg 或本地播放器 | 讀取代理提供的清單。FFmpeg 封裝輸出檔，VLC、IINA 或 hls.js 可用於播放。 |

## 3. 核心模組

### 3.1 輸入層

命令介面為 `hls-harvester <page-url> [--download | --play] [--quality <quality>] [--output <path>]`。預設下載，`--play` 則啟動本地代理供播放器連線。`--quality` 從已選影片的可用畫質中選取，超出選項時列出可用值。HTTP API 屬未來擴充。

### 3.2 擷取層

1. 建立獨立的瀏覽器 context，**在導覽前註冊 `response` 監聽器**，再開頁並在需要時點擊播放。設定擷取期限，持續有網路流量的頁面也要能結束擷取。
2. 以 URL、HLS MIME 或播放器發出的文字回應尋找候選，涵蓋無副檔名的清單。在有限的讀取量內確認 `#EXTM3U` 並用 HLS parser 解析。MP4 預告、TS/fMP4 分段或無法解析的文字都不能單憑 MIME 入選。
3. 將 master playlist、其 variants 與替代音軌歸為同一部影片。可播放的獨立 media playlist 也可成為候選。若同頁有多部影片，優先採用能與目標播放器動作建立關聯者。仍有歧義時列出候選供選擇。無人值守時回報歧義並停止下載。
4. 從 `og:title`、頁面標題、`h1` 或站點 selector 取得名稱，清理後作為預設檔名。擷取結果保留候選清單、畫質關聯、工作階段參照和可得的授權到期時間。日誌只記錄候選代號與失敗原因。

### 3.3 快取與憑證

- 快取鍵由頁面來源（scheme、host、port）、站點內影片 ID 或能區分內容的正規化頁面 URL，以及不含憑證的工作階段識別值組成。若頁面 URL 帶有敏感參數，使用工作階段內的不透明代號索引。切換帳號、登出或結束匿名工作階段時隔離或淘汰舊項目。
- 同頁多片時快取候選與關聯，每次命中仍依第 3.2 節選片。上次的人工選擇只適用於當次工作。
- 可在 SQLite 或 Redis 保存標題、畫質與到期時間。Cookie jar、自訂認證標頭與帶簽章的 URL 留在對應工作階段的記憶體中。程序重啟後，只有公開中繼資料的紀錄視為未命中。
- 快取存活時間可按站點設定（建議 5–15 分鐘），且不得晚於已知的清單或憑證到期時間。若使用已快取的擷取結果收到 401/403，淘汰該項並在相同工作階段重新擷取一次。再失敗就回報原因。下載中的半成品不得標記為成功。
- 代理送出每次請求及跟隨每一跳重新導向前，依目的 URL 的 domain、path、secure 等條件從 cookie jar 選取 Cookie。`Authorization` 及站點自訂認證標頭限於獲授權的 origin，`Referer` 依該目的地的規則產生。從瀏覽器擷取的整組 headers 不可套用到所有子資源。

### 3.4 播放與下載

**共用本地代理。** 代理綁定 loopback，僅受理本次工作已登記的資源，為其分配不含上游網址的本地路徑。播放器與 FFmpeg 只取得這些本地 URL，不必接收上游 Cookie 或簽名網址。代理依以下規則服務清單與媒體。

- 每層清單都以該層**跟隨重新導向後的最終 URL** 為基準解析相對 URI。遞迴代理 master 指向的 variant、`EXT-X-MEDIA` 指向的音軌或字幕清單，以及 media playlist 內的分段。指定畫質時，回傳只含所選 variant 及其引用音軌、字幕群組的 master，保留影音軌關聯。
- 保留 `EXT-X-MAP` 初始化資源及 `EXT-X-BYTERANGE` 語意。對用戶端的範圍請求保留所需的 Range、206 狀態及 Content-Range。一般 AES-128（identity）金鑰 URI 也須經同一憑證選取流程取得。遇到不支援的 URI 型標籤或加密方式時回報具體原因，避免交付殘缺清單。
- 播放仍在更新的 media playlist 時，代理向上游刷新清單，保留媒體序號。下載完整檔案以已有結尾（`EXT-X-ENDLIST`）的影片為驗收範圍。沒有結尾時提示改用播放模式。

**完整下載（預設）。** FFmpeg 讀取已選畫質的本地清單，範例中的 `playback_url` 與 `output_file` 由呼叫端提供。程式以 subprocess 參數陣列執行下列等價命令，無需拼接多行 HTTP 標頭。

```bash
ffmpeg -nostdin -i "$playback_url" -c copy -movflags +faststart "$output_file"
```

下載時先寫入同目錄、保留容器副檔名的暫存檔。FFmpeg 成功結束並確認輸出有效後才發佈為最終檔名，失敗時回報錯誤並清理半成品。

**即時播放。** 回傳工作階段內的 loopback 播放清單 URL。使用者在本機開啟該 URL。工作階段結束時，代理一併撤銷其資源映射。

### 3.5 適配器層

通用適配器提供網路事件觀察與標題提取。站點適配器可依 domain 註冊，補充播放器啟動動作、候選關聯或標題 selector。兩者的輸出都經相同的清單解析、工作階段隔離與代理流程。專用適配器失敗時可回退通用流程。需要登入或互動確認時向使用者說明。

## 4. 使用流程

CLI 先以來源、影片及工作階段查詢快取。未命中時啟動擷取並保存候選。命中與未命中都經過選片，代理才為選定影片建立本地播放 URL，播放模式立即回傳，下載模式則等待 FFmpeg 完成。只有檔案通過驗證才回報成功與最終路徑。

## 5. 技術棧建議

首選 Python、Playwright、HLS parser、aiohttp、SQLite 與系統 FFmpeg/ffprobe。單機可先用 SQLite，後續可替換為 Redis。替代實作可採 Node.js，沿用第 7 節驗收條件。

## 6. 建議檔案結構

```text
src/
  cli.py           命令列與工作階段生命週期
  capturer.py      Playwright 監聽與候選辨識
  cache.py         依來源及工作階段隔離快取
  proxy.py         解析清單、映射資源與選取上游憑證
  downloader.py    啟動 FFmpeg 與驗證輸出
  adapters/        通用與站點專用適配器
tests/fixtures/    可重播的本機頁面與 HLS 樣本
```

## 7. 實作驗收

以下為實作完成後應通過的案例。本機 fixture 使用合成影音與測試憑證，可以在沒有外部影音站與模型服務的環境執行。

| 案例 | 通過條件 |
|---|---|
| 開頁即預載 | 測試頁只請求一次無副檔名的 HLS 清單，點播放時沿用。擷取器仍選到該清單，並排除同頁的 MP4 預告及 TS 分段。 |
| 同頁多部影片 | 同一 master 的三種畫質只算一部影片。另有獨立預告且來源關聯不足時，互動模式要求選擇。再次命中快取仍可改選預告，無人值守仍回報歧義。 |
| 完整下載 | CLI 從本機頁面找出兩秒 fMP4 VOD，經代理取得子清單、初始化資源與分段。FFmpeg 成功，ffprobe 讀到預期影音軌，容器時長與兩秒相差不超過 0.1 秒。失敗時最終路徑不出現半成品。 |
| 清單重寫 | 樣本含重新導向後的相對 URI、外掛音軌、初始化資源、byte-range 與一般 AES-128 金鑰。播放器取得的資源 URL 全部指向 loopback，取得的範圍及解碼結果符合樣本。指定畫質下載分離音視軌的樣本時，ffprobe 須同時讀到所選畫質及預期音軌。 |
| 憑證轉送 | 兩個測試 hostname 分別提供來源站與 CDN。來源站收到適用的 Cookie 及 Referer。CDN 只收到自身適用的憑證。以清單直接引用及 HTTP 重新導向各驗一次，並核對 FFmpeg 參數與日誌均不含上游憑證。 |
| 快取與過期 | 兩站共用影片 ID、同頁切換帳號均各自命中正確內容。過期或程序重啟後重新擷取。模擬 403，確認只觸發一次重新擷取，持續失敗時回報錯誤。 |
| 即時播放 | 更新中的清單新增分段時，本地播放器能取得後續分段。完整下載模式遇到相同清單時提示改用播放模式。 |

## 8. AI 選片實驗與後續擴充

先用第 3.2 節的規則建立基準。要回答的問題是「當同頁有多份可播放的 HLS 清單時，模型能否提高選中正片的比例，同時避免下載錯片？」唯一可判定的候選繼續由規則直接選取。

1. 收集自有或獲授權頁面的候選，人工標記目標影片及資訊不足的案例。將同站樣本分到同一組，保留整站作測試，避免同站的播放器特徵同時出現在調整集與測試集。
2. 模型只接收匿名候選 ID、可取得的時長、影音軌、畫質關係及相對播放動作的時間差。缺值明示為未知。輸出限於當次候選 ID 或棄答。棄答或無效輸出回到第 3.2 節的歧義處理，無人值守時直接結束。模型輸入不含原頁、Cookie、認證標頭、簽名 URL 或影音本體。
3. 在同一批保留樣本上離線比較「規則」與「規則加模型」。分別報告誤選數／自動選取數、自動選取數／總案例數、正確自動選取數／總案例數，另記每頁推論成本與延遲。先看誤選與覆蓋的取捨，再決定是否提供預設關閉的線上選項。模型不可用時沿用第 3.2 節流程。

開發時可讓 coding agent 根據去識別化的失敗事件與人工指定的預期結果提出適配器及回歸測試的 Draft PR，經驗收後由維護者審查。後續可擴充播放時同步錄製、TS 檔案輸出、並行下載佇列、更多適配器、Web UI 與容器部署。

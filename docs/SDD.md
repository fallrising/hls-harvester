# Software Design Document: hls-harvester

## 1. 概述

hls-harvester 接受影片頁面 URL，在獨立的 Playwright 瀏覽器中找出播放器使用的 HLS 播放清單，供使用者在本機播放或下載。適用於有權存取與保存的影音，包括播放後才載入清單、網址帶有短效簽章，以及清單與影音分段由不同網域提供的情況。

「乾淨播放」指本地播放器只讀媒體，不載入原頁的腳本、彈窗及跳轉。原先已插入媒體串流的廣告會隨影音保留。串流播放也受上游可用性和網路狀況影響。

本文件定義預期行為。第一個實作里程碑是以本機測試頁完成「輸入 URL → 擷取 → 下載 → 用 ffprobe 驗證輸出」。播放與下載共用同一套清單解析與上游請求核心：播放經本地 HLS 代理，下載由分段下載器直接取得資源。AI 選片是選做實驗，基本流程可以離線驗收。

### 1.1 範圍與非目標

- **範圍內：** 使用者有權存取的頁面；未加密或一般 AES-128（identity key）HLS；使用者自行登入取得的工作階段。
- **非目標：** DRM 影音（Widevine、FairPlay、PlayReady、`SAMPLE-AES` 及 `EXT-X-KEY` 的非 identity `KEYFORMAT`），偵測到時回報「受 DRM 保護，不支援」並停止；繞過付費牆、登入、地區限制或其他存取控制；繞過 CAPTCHA 或機器人偵測；移除串流內已插入的廣告。
- 使用者須自行確認對目標內容的權利及網站條款。工具不內建繞過站點限制的手段。

## 2. 系統架構

| 元件 | 責任 |
|---|---|
| CLI | 接收頁面 URL、模式、畫質與輸出路徑，回傳本地播放 URL 或已完成的檔案路徑，並以固定的結束碼回報結果（§3.8）。 |
| Playwright 與站點適配器 | 觀察播放器請求，處理彈窗與跳轉，解析 HLS 候選、媒體間的關係與標題，並記錄每個上游 host 的請求標頭樣板。 |
| 上游請求核心 | 共用的清單解析、URI 解析、憑證選取與重試邏輯。播放代理與下載器都經由它存取上游。 |
| 本地 HLS 代理（播放） | 重寫清單 URI 為本地路徑，依目的地取得資源，僅服務已登記資源。 |
| 分段下載器（下載） | 並行取得分段、處理憑證過期與續傳，將分段寫入工作目錄後交由 FFmpeg 重新封裝。 |
| FFmpeg / ffprobe | 從本地分段封裝輸出檔並驗證。VLC、IINA 或 hls.js 可用於播放。 |

### 2.1 程序模型

- **v1：單次執行的 CLI。** 每次執行是一個獨立程序，擷取、下載或播放在同一程序內完成，憑證只存在該程序記憶體中。v1 不提供跨執行的擷取快取，因為短效憑證無法安全地跨程序保存，跨程序快取在此模型下永遠不會命中。
- **v2：常駐服務 `hls-harvester serve`。** 長時間執行的本機服務持有瀏覽器 context 與工作階段，CLI 成為其用戶端。§3.3 的擷取快取只在此模式啟用。

## 3. 核心模組

### 3.1 輸入層

```text
hls-harvester get <page-url> [--download | --play] [--quality <q>] [--output <path>]
                  [--storage-state <file>] [--headed] [--resume] [--non-interactive]
hls-harvester login <site-url> --storage-state <file>
hls-harvester doctor
```

- `get` 預設下載，`--play` 啟動本地代理供播放器連線。`--quality` 從已選影片的可用畫質中選取，超出選項時列出可用值並以結束碼 2 結束。
- `login` 開啟有視窗的獨立瀏覽器讓使用者自行登入，結束時將 Playwright `storage_state` 寫入指定檔案（權限 0600）。`get --storage-state` 載入該檔建立 context。工具從不要求或保存使用者密碼。
- `doctor` 檢查 Python 版本、FFmpeg/ffprobe 版本、Playwright 瀏覽器是否已安裝，以及設定檔是否有效。
- HTTP API 屬 v2 常駐服務的範圍。

### 3.2 擷取層

1. **瀏覽器模式。** 預設無視窗（headless）。可由 `--headed` 或站點設定改用有視窗模式，用於需要使用者互動或對無視窗瀏覽器行為不同的站點。工具不實作反機器人偵測規避。站點拒絕服務時回報原因。
2. **監聽。** 建立獨立的瀏覽器 context（`service_workers="block"`，讓所有請求都在網路層可見），**在導覽前於 context 層註冊 `request`／`response` 監聽器**，因此 iframe 內播放器與新開分頁的請求都能觀察到。設定擷取期限（預設 45 秒，可依站點設定），持續有網路流量的頁面也要能結束擷取。
3. **彈窗與跳轉。** 記錄目標頁面。`context` 新開的分頁若非使用者指定的目標，記錄後關閉。主框架被導向其他 origin 時，返回目標頁並重新嘗試，最多三次。點擊播放後若無候選出現，等待短暫間隔再點擊，最多三次。站點適配器可提供關閉遮罩或播放按鈕的 selector。所有次數上限皆可設定，用盡後回報「找不到播放器請求」。
4. **候選辨識。** 以 URL、HLS MIME 或播放器發出的文字回應尋找候選，涵蓋無副檔名的清單。在有限的讀取量內確認 `#EXTM3U` 並用 HLS parser 解析。MP4 預告、TS/fMP4 分段或無法解析的文字都不能單憑 MIME 入選。若播放器有發出分段請求但找不到可解析的清單（例如清單在頁面腳本中解碼後以 `blob:` URL 交給播放器），回報「清單不可觀察」並停止。
5. **選片。** 將 master playlist、其 variants 與替代音軌歸為同一部影片。可播放的獨立 media playlist 也可成為候選。若同頁有多部影片，優先採用能與目標播放器動作建立關聯者。仍有歧義時列出候選供選擇。`--non-interactive` 時回報歧義並以結束碼 3 結束。
6. **請求標頭樣板。** 對每個被選影片使用的上游 host，記錄播放器實際送出的非憑證標頭（`User-Agent`、`Origin`、`Referer`、`Accept` 等）作為該 host 的樣板。`Cookie` 不納入樣板，改由 cookie jar 依 §3.3 選取。`Authorization` 及站點自訂認證標頭只記錄到實際收到它們的 origin。
7. **標題。** 從 `og:title`、頁面標題、`h1` 或站點 selector 取得名稱，清理後作為預設檔名（移除路徑分隔字元及控制字元，限制長度，避免與既有檔案衝突）。
8. 擷取結果保留候選清單、畫質關聯、工作階段參照、標頭樣板和可得的授權到期時間。日誌只記錄候選代號與失敗原因。

### 3.3 工作階段、憑證與快取

**上游請求。** 預設以 Playwright `BrowserContext.request` 送出所有上游請求。它與頁面共用 cookie jar，自動依 RFC 6265 的 domain、path、secure 規則選取 Cookie，核心以 `max_redirects=0` 送出請求並自行跟隨重新導向（上限 10 跳），每一跳都依目的 URL 重新選取 Cookie 並重新套用下列標頭規則。核心在其上套用 §3.2 的 host 標頭樣板。

- 沒有樣板的 host（例如重新導向到新的 CDN）只帶 `User-Agent`，以及依該目的地規則產生的 `Referer`。
- `Authorization` 及站點自訂認證標頭限於擷取時觀察到的 origin，重新導向到其他 origin 時移除。
- 從瀏覽器擷取的整組 headers 不可套用到所有子資源。
- 若 CDN 依 TLS 或 HTTP/2 指紋拒絕非瀏覽器請求，v1 回報「上游拒絕非瀏覽器請求」並停止。由頁面內 `fetch` 轉送的替代方案受 CORS 限制，列為後續研究。

**擷取快取（僅 v2 常駐服務）。**

- 快取鍵由頁面來源（scheme、host、port）、站點內影片 ID 或能區分內容的正規化頁面 URL，以及不含憑證的工作階段識別值組成。若頁面 URL 帶有敏感參數，使用工作階段內的不透明代號索引。切換帳號、登出或結束匿名工作階段時隔離或淘汰舊項目。
- 同頁多片時快取候選與關聯，每次命中仍依 §3.2 選片。上次的人工選擇只適用於當次工作。
- 可在 SQLite 保存標題、畫質與到期時間。Cookie jar、認證標頭與帶簽章的 URL 留在常駐服務記憶體中。服務重啟後，只有公開中繼資料的紀錄視為未命中。
- 快取存活時間可按站點設定（建議 5–15 分鐘），且不得晚於已知的清單或憑證到期時間。使用已快取的擷取結果收到 401/403 時，淘汰該項並在相同工作階段重新擷取一次，再失敗就回報原因。

### 3.4 清單處理（共用）

- 每層清單都以該層**跟隨重新導向後的最終 URL** 為基準解析相對 URI。遞迴處理 master 指向的 variant、`EXT-X-MEDIA` 指向的音軌或字幕清單，以及 media playlist 內的分段。指定畫質時只保留所選 variant 及其引用音軌、字幕群組，保留影音軌關聯。
- 保留 `EXT-X-MAP` 初始化資源及 `EXT-X-BYTERANGE` 語意。一般 AES-128（identity）金鑰 URI 也經同一憑證選取流程取得。遇到 §1.1 列出的 DRM 或其他不支援的 URI 型標籤時，回報具體標籤與原因，避免交付殘缺清單。
- 依 `EXT-X-DISCONTINUITY` 將 media playlist 切分為多個區段（period），記錄各區段的分段範圍。

### 3.5 下載

**分段下載器。** 下載模式不經代理，直接由核心取得資源：

1. 解析所選畫質的 media playlist（含音軌、字幕），僅接受已有 `EXT-X-ENDLIST` 的清單。沒有結尾時提示改用播放模式並以結束碼 2 結束。
2. 在輸出目錄旁建立工作目錄 `.<name>.hlsh/`，寫入 `job.json`：來源頁面、所選候選、各分段的序號、大小與完成狀態。工作目錄與暫存檔建立時權限為 0700／0600，`job.json` 不含任何憑證或簽章 URL。
3. 以有界並行（預設每個 host 4 條連線，可設定）取得初始化資源、金鑰與分段，寫入工作目錄。每個請求有連線與讀取逾時（預設 10 秒／30 秒）。暫時性錯誤（逾時、連線重設、429、5xx）以指數退避加隨機抖動重試，最多 5 次，並遵守 `Retry-After`。
4. **憑證於下載中過期。** 分段收到 401/403 時暫停該 variant 的新請求，先重新請求 media playlist 原 URL。若失敗，則在同一瀏覽器工作階段重新擷取（重新開頁），以媒體序號（`EXT-X-MEDIA-SEQUENCE` 加索引）對齊新舊清單，僅以新 URL 取得尚未完成的分段。對齊失敗（分段數或時長不符）時停止並回報。每次工作最多重新擷取 3 次。
5. **續傳。** `--resume` 讀取既有 `job.json`，重新擷取以取得新憑證，對齊序號後只下載未完成或大小不符的分段。不帶 `--resume` 而工作目錄已存在時，提示使用者選擇續傳或重新開始。

**重新封裝。** 所有分段完成後，產生只指向本地檔案的清單，由 FFmpeg 以 subprocess 參數陣列執行：

```bash
ffmpeg -nostdin -allowed_extensions ALL -protocol_whitelist file,crypto \
       -i "$local_playlist" -c copy -movflags +faststart "$tmp_output"
```

- **不連續區段。** 只有一個區段時直接封裝。多個區段時，先以 ffprobe 比對各區段的編碼、解析度、取樣率與聲道。全部一致時，各區段分別封裝後以 concat demuxer 合併（`-c copy`），避免時間戳跳躍造成的錯誤輸出。不一致時回報「區段參數不同」並停止，或在使用者明確指定 `--reencode` 時重新編碼為第一個主要區段的參數。
- 先寫入同目錄、保留容器副檔名的暫存檔。FFmpeg 成功結束、ffprobe 讀到預期影音軌且總時長與清單時長相差不超過 0.5 秒（或 0.5%，取較大者）後，才改名為最終檔名並刪除工作目錄。失敗時保留工作目錄供續傳，最終路徑不得出現半成品。

### 3.6 即時播放（本地代理）

- 代理綁定 `127.0.0.1` 的隨機埠，每個工作階段產生 128 位元隨機路徑前綴，所有資源路徑都位於該前綴下且不含上游網址。
- 只接受 `Host` 為 `127.0.0.1:<port>` 或 `localhost:<port>` 的請求，其他一律 403，以防 DNS rebinding。帶有 `Origin` 的請求只接受設定的本地播放器頁面 origin，不回傳萬用 CORS 標頭，防止使用者瀏覽器中的其他網頁讀取代理。
- 僅受理本次工作已登記的資源。清單刷新時新出現的 URI 即時登記，未登記的路徑回 404。
- 代理轉送用戶端的 `Range` 請求，保留 206 狀態及 `Content-Range`。
- 播放仍在更新的 media playlist 時，代理依 `EXT-X-TARGETDURATION` 向上游刷新清單，保留媒體序號。上游清單刷新收到 401/403 時，依 §3.5 第 4 點重新取得憑證。
- 回傳 loopback 播放清單 URL 給使用者，由使用者在本機開啟。無播放器請求超過閒置期限（預設 10 分鐘）或使用者按 Ctrl-C 時，代理撤銷資源映射並結束。

### 3.7 適配器層

通用適配器提供網路事件觀察、彈窗處理與標題提取。站點適配器可依 domain 註冊，補充播放器啟動動作、遮罩關閉 selector、候選關聯或標題 selector。兩者的輸出都經相同的清單解析、工作階段隔離與上游請求流程。專用適配器失敗時可回退通用流程。需要登入或互動確認時向使用者說明，並提示使用 `login` 子命令。

### 3.8 設定、日誌與結束碼

**設定檔。** `$XDG_CONFIG_HOME/hls-harvester/config.toml`（macOS 為 `~/Library/Application Support/hls-harvester/config.toml`），可被命令列參數覆寫。

```toml
[defaults]
output_dir = "~/Videos"
capture_timeout_s = 45
concurrency_per_host = 4
headless = true

[sites."example.com"]
headless = false
play_selector = "button.play"
cache_ttl_s = 600   # 僅 v2 常駐服務
```

**日誌。** 預設輸出到 stderr，`-v`／`-vv` 提高層級，`--log-json` 輸出結構化日誌。所有日誌都經過遮罩：URL 只保留 scheme、host 與路徑，查詢字串、`Cookie`、`Authorization` 及樣板中的認證標頭一律以 `<redacted>` 取代。FFmpeg 的 stderr 經同一遮罩處理後才寫入日誌。

**結束碼。**

| 碼 | 意義 |
|---|---|
| 0 | 成功（下載完成並通過驗證，或播放正常結束） |
| 1 | 未預期的內部錯誤 |
| 2 | 使用方式錯誤（參數、畫質不存在、清單無結尾卻要求下載） |
| 3 | 選片有歧義，需人工選擇 |
| 4 | 擷取失敗（找不到播放器請求、清單不可觀察、擷取逾時） |
| 5 | 上游錯誤（重試用盡、憑證重新取得失敗、上游拒絕非瀏覽器請求） |
| 6 | 不支援的內容（DRM、不支援的標籤或加密方式） |
| 7 | 輸出驗證失敗（FFmpeg 失敗、軌道或時長不符、區段參數不同） |

### 3.9 安裝與平台

- Python 3.11 以上，以 `pipx install hls-harvester` 安裝。安裝後執行 `playwright install chromium`，`doctor` 會檢查並提示。
- 需要系統 FFmpeg/ffprobe 6.0 以上。
- 正式支援 macOS 與 Linux。Windows 盡力支援，路徑與檔名清理需涵蓋 Windows 保留字元。

## 4. 使用流程

1. CLI 讀取設定，載入 `--storage-state`（若有），建立瀏覽器 context。（v2 常駐服務先以來源、影片及工作階段查詢快取。）
2. 擷取層處理彈窗與跳轉，取得候選並選片，記錄標頭樣板。
3. 播放模式：代理為選定影片建立本地播放 URL 並立即回傳，直到閒置或使用者中斷。
4. 下載模式：分段下載器取得所有分段，必要時重新取得憑證，完成後重新封裝並驗證。只有檔案通過驗證才回報成功與最終路徑，否則以 §3.8 結束碼回報。

## 5. 技術棧

Python 3.11+、Playwright（Chromium）、`m3u8` 或同等 HLS parser、`asyncio`、aiohttp（僅代理伺服器端）、SQLite（v2 快取）、系統 FFmpeg/ffprobe。替代實作可採 Node.js，沿用第 7 節驗收條件。

## 6. 建議檔案結構

```text
src/hls_harvester/
  cli.py           命令列、設定與結束碼
  config.py        設定檔載入與站點設定合併
  capturer.py      Playwright 監聽、彈窗處理、候選辨識與標頭樣板
  upstream.py      共用上游請求：憑證選取、標頭套用、重試與逾時
  playlist.py      清單解析、URI 解析、畫質篩選、不連續區段
  downloader.py    分段下載、續傳、憑證重新取得、FFmpeg 封裝與驗證
  proxy.py         播放代理：本地路徑映射、Host／Origin 檢查、清單刷新
  redact.py        日誌遮罩
  cache.py         （v2）依來源及工作階段隔離的擷取快取
  adapters/        通用與站點專用適配器
tests/fixtures/    可重播的本機頁面、HLS 樣本與故障注入伺服器
```

## 7. 實作驗收

以下為實作完成後應通過的案例。本機 fixture 使用合成影音與測試憑證，可以在沒有外部影音站與模型服務的環境執行。故障注入伺服器可依設定回傳逾時、429、5xx、401/403 及憑證到期。

| 案例 | 通過條件 |
|---|---|
| 開頁即預載 | 測試頁只請求一次無副檔名的 HLS 清單，點播放時沿用。擷取器仍選到該清單，並排除同頁的 MP4 預告及 TS 分段。 |
| 彈窗與跳轉 | 第一次點擊播放開啟新分頁並將主框架導向另一 origin。擷取器關閉新分頁、返回目標頁，第二次點擊後選到正確清單。iframe 內的播放器請求同樣能被選到。 |
| 同頁多部影片 | 同一 master 的三種畫質只算一部影片。另有獨立預告且來源關聯不足時，互動模式要求選擇，`--non-interactive` 以結束碼 3 結束。 |
| 完整下載 | CLI 從本機頁面找出兩秒 fMP4 VOD，取得子清單、初始化資源與分段。FFmpeg 成功，ffprobe 讀到預期影音軌，時長誤差在 §3.5 範圍內。失敗時最終路徑不出現半成品。 |
| 長片與憑證過期 | 600 個分段的 VOD，分段簽章在下載進行到約一半時過期。下載器重新取得憑證並依序號對齊，最終輸出完整且通過驗證。重新擷取次數不超過 3 次。 |
| 暫時性錯誤 | 隨機 10% 的分段請求回傳逾時、429（含 `Retry-After`）或 503。下載仍成功，且每個 host 的並行連線數不超過設定值。 |
| 續傳 | 下載到一半時終止程序。`--resume` 只下載未完成的分段，最終輸出與一次下載完成的結果位元組相同。 |
| 不連續區段 | 樣本含三個參數相同的區段（模擬插入廣告），輸出時長正確且無時間戳錯誤。另一個參數不同的樣本以結束碼 7 結束，加 `--reencode` 則成功。 |
| 清單重寫 | 樣本含重新導向後的相對 URI、外掛音軌、初始化資源、byte-range 與一般 AES-128 金鑰。播放器取得的資源 URL 全部指向 loopback，取得的範圍及解碼結果符合樣本。指定畫質下載分離音視軌的樣本時，ffprobe 須同時讀到所選畫質及預期音軌。 |
| 不支援內容 | `SAMPLE-AES` 及 Widevine `KEYFORMAT` 樣本以結束碼 6 結束並指出具體標籤。清單以 `blob:` 交給播放器的頁面以結束碼 4 結束。 |
| 憑證轉送 | 兩個測試 hostname 分別提供來源站與 CDN。來源站收到適用的 Cookie、Referer 與 User-Agent。CDN 只收到自身適用的憑證，且 `Authorization` 不會跟隨重新導向到 CDN。以清單直接引用及 HTTP 重新導向各驗一次，並核對 FFmpeg 參數、`job.json` 與日誌均不含上游憑證或查詢字串。 |
| 代理安全 | `Host: attacker.example` 或未登記路徑的請求回 403／404。來自其他 origin 的帶 `Origin` 請求不取得 CORS 標頭。猜測路徑前綴不可行（前綴長度 ≥ 128 位元）。 |
| 即時播放 | 更新中的清單新增分段時，本地播放器能取得後續分段。完整下載模式遇到相同清單時以結束碼 2 提示改用播放模式。閒置超時後代理結束。 |
| 登入工作階段 | `login` 產生的 `storage_state` 檔權限為 0600。`get --storage-state` 能存取需登入的測試頁，未帶時回報需要登入。 |
| （v2）快取與過期 | 兩站共用影片 ID、同頁切換帳號均各自命中正確內容。過期或服務重啟後重新擷取。模擬 403，確認只觸發一次重新擷取，持續失敗時回報錯誤。 |

## 9. AI 選片實驗與後續擴充

先用 §3.2 的規則建立基準。要回答的問題是「當同頁有多份可播放的 HLS 清單時，模型能否提高選中正片的比例，同時避免下載錯片？」唯一可判定的候選繼續由規則直接選取。此實驗在 M4 累積真實站點樣本後才開始。

1. 收集自有或獲授權頁面的候選，人工標記目標影片及資訊不足的案例。將同站樣本分到同一組，保留整站作測試，避免同站的播放器特徵同時出現在調整集與測試集。
2. 模型只接收匿名候選 ID、可取得的時長、影音軌、畫質關係及相對播放動作的時間差。缺值明示為未知。輸出限於當次候選 ID 或棄答。棄答或無效輸出回到 §3.2 的歧義處理，無人值守時直接結束。模型輸入不含原頁、Cookie、認證標頭、簽名 URL 或影音本體。
3. 在同一批保留樣本上離線比較「規則」與「規則加模型」。分別報告誤選數／自動選取數、自動選取數／總案例數、正確自動選取數／總案例數，另記每頁推論成本與延遲。先看誤選與覆蓋的取捨，再決定是否提供預設關閉的線上選項。模型不可用時沿用 §3.2 流程。

開發時可讓 coding agent 根據去識別化的失敗事件與人工指定的預期結果提出適配器及回歸測試的 Draft PR，經驗收後由維護者審查。後續可擴充播放時同步錄製、TS 檔案輸出、並行下載佇列、更多適配器、Web UI 與容器部署。
